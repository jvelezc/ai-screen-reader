## Purpose

Prove that a worker losing its actual server lease during a recorded route cannot
claim completion or replay uncertain input. Retain the original scope/generation,
actual source/action/result prefix and unavailable media explicitly. An engine/
authority failure is not an accessibility barrier.

## Declared bounded trial

Admit one new sanitized route through the original account while the idle worker
is frozen under an owned thaw guard. Confirm queued/gen0/zero attempts/leases.
Resume normal acquisition and watch only this gen1 job's durable command journal.
After an input intent is retained, briefly hold its exact native container and
coordinator. Confirm the actual leased organization/job/generation/worker and
paused/frozen state; never read or print the lease token/hash.

Force expiry of only this exact lease's expires_at on the real database, returning
only non-secret scope/time metadata. Do not restore or resurrect the expired lease.
This is a controlled forced server-lease expiry, separate from natural TTL aging,
provider-token expiry and network outage. Independently bounded unpause/thaw guards
must release the exact owned resources even if the observer disconnects.

Resume the normal worker, inspect retained command/source facts and database state,
and independently confirm owned native absence. An intended command without an
observed result remains uncertain. Previously authorized input may have happened;
no helper dispatches website input and no failed attempt is replayed. Check that
there is no unfenced completion, silent fresh-generation replay or false archive
claim. A distinct normal job must recover capacity after the fault settles.

## Done when

The actual expired attempt cannot acquire fresh authority or publish completion,
its original facts/uncertainty remain intact, cleanup is independently confirmed,
all owned guards settle and a distinct normal original-account job succeeds.
If the bounded hold misses its target or expiry updates no exact active lease,
record the trial as unproven and retain it. Do not call preparation acceptance.

## Newly exposed consumer gap

Before queue recovery, raw leased/Pending does not tell API/MCP clients that the
actual permission has expired. The current MCP advice can keep polling a safely
stopped worker. Next implement an explicit, tenant-scoped, server-time permission
snapshot and recovery advice without rewriting execution state, inferring input
or granting replay authority. Keep remaining publication/network/provider/website/
intervention/operations/humanAT gates separate.
