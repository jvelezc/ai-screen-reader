# Remaining product completion gates

October 28, 2026. Product: Privensic Screen Reader. This is the ordered remainder
of the original plan, not a claim that all milestones are complete. The original
proposal under `outputs/` is unchanged. Read [current delivery evidence](validation/recorded-evidence-claims-v1.md)
for the accepted recorded-claim slice and its controlled-fixture limits.

## Accepted: verify assessment claims against recorded originals

Core1.9, existing Edge v6 and UIe8cfb2d join these contracts. The original account
verified fresh reached/Unknown recordings and rejected an altered success claim.
Old recordings retain missing context. Local Windows and Windows/Ubuntu CI pass
2,397 each; UI439 each, exact private deployment151 hashes and independent S3
checks pass. [Acceptance receipt](validation/recorded-evidence-claims-v1.md).
The delivered requirements below apply to controlled fixtures; they do not
complete arbitrary website collection or authorize a real website package.

1. Resolve the authorized tenant, scan, job, generation and actual producer from
   durable metadata; verify complete bound recording originals. An operator
   import or caller-provided worker ID cannot replace admission provenance.
2. Bind each supported claim to the actual run, document, observation, attempt
   and event sequence. Verify declared keys, completed input, focus/AX context
   and observed result against retained facts. A hash only proves byte integrity.
3. Preserve distinct suspected, documented, missing, contradictory, Unknown,
   engine-error and policy-denied states. Require real separate repeat/comparator
   support where the eight-condition policy demands it. Never manufacture a
   pointer success, second attempt, legal conclusion or video/event association.
4. Expose the proof and missing conditions through the independently usable API
   and private MCP; consume that response through existing Supabase Edge. Keep
   URL-only `ScanResultsRequired` until actual target collection exists.

**Done when:** a real admitted route supports only the facts it actually retained
after reconnect. Changed scope, invented events, unrelated originals, changed
input/goal outcomes and absent repeat/comparator support cannot yield Ready.
Demonstrate the reached and Unknown routes through the original account, plus
deterministic rejection tests, actual Chromium and both CI platforms. A complete
single route need not be a sufficient website-evidence package.

## Next: recover interrupted recordings safely

The first safeguard blocks an expired keyboard lease instead of allocating a
replacement attempt. It retains the original worker/generation and a visible
`WORKER_INPUT_OUTCOME_UNCONFIRMED` reason. Stopped-source assessment requires a
recording instead of suggesting that waiting will finish collection. Safe
zero-input observation/passive retries remain available. This fence alone does
not recover partially saved recordings or establish crash-after-input acceptance.
See the [recovery validation record](validation/interrupted-recording-recovery-v1.md).

Exercise the actual Linux worker under crash after input, upload before metadata
commit, storage outage, lease expiry, cancellation and full staging disk. Retain
durable intent and the last confirmed state. Recovery must distinguish uncertain
input from successful input, avoid silently reexecuting it, reject stale attempt
publication and remove only independently verified owned containers. Failed
publication must stay visible with its safe error and next action.

**Done when:** injected failures preserve originals and attempt identity, cannot
replace a completed receipt, cannot report a successful goal from uncertain
input, and recover bounded capacity after restart. Keep actual native recovery,
storage reconstruction and database fencing receipts separately.

## Then: validate real hosted authority loss

Use isolated test workspaces under the intended application identity. Test real
provider-token expiry and membership revocation during observation, graph read,
original-file paging and playback loading. Confirm the API and Edge deny current
access, the notebook clears results and media, and native reader ownership is
retired or remains explicitly unresolved. Do not revoke unrelated memberships or
substitute a privileged service identity for application-user acceptance.

**Done when:** actual provider/RLS denials and exact native absence are retained
for each tested lifecycle. Synthetic-provider tests and a merely expired local
reader are not evidence that provider membership revocation was exercised.

## Then: bounded website goal collection

Extend the proven exact-host policy and independent egress isolation to one
declared unauthenticated target/task at a time. State supported controls, initial
state and exploration budget before collection. Retain actual attempted paths
and outcomes; diagnostic feature hints cannot repair reader names or become
observations. Preserve authentication-required and unsupported controls as
explicit limits. General credential entry remains behind the remote capture
exclusion/intervention gate.

**Done when:** an approved controlled website outside the bundled fixture runs
through admission, isolated collection, verified originals and assessment with
the intended account. Private-address, DNS/redirect/frame/popup/WebSocket bypass
tests remain green. An unknown target must never receive fabricated findings.

## Then: hosted intervention and assistive-technology acceptance

Connect the existing exclusive controller and exclusion protocol to scoped
remote viewer/input authority. Prove same-context continuity, stale-generation
denial, complete input/write/media drain, fresh baseline on resume and immediate
view revocation. Test synthetic credentials first. Keep human assistance explicit
in the attempt history and distinguish current pixels from retained semantics.

**Done when:** an actual authorized person can use the hosted viewer, pause,
take over, resume and close, with independent privacy/native cleanup evidence.
Record the supported viewer/client and real assistive-technology results. Coding
or agent-operated checks cannot establish this person's usability acceptance.

## Release gate: operations and supported scope

Complete bounded quotas/cancellation, queue and evidence-backlog diagnostics,
retention/deletion, backup restoration, storage/disk/browser failure runbooks and
exact tested deployment/rollback receipts. Publish the supported profile,
browser/image/collector versions, limits and named client acceptance. Keep local
Windows, Linux, CI, deployment, tenant use and human/AT results separate.

The first supported release requires the preceding gates for its declared
scope. It does not promise universal website accessibility. Plaintiff disability,
personal injury/encounter, standing, jurisdiction/liability, custody and judicial
admissibility remain outside the automated website-side assessment. No human
review task is inserted into that decision workflow.

Public MCP hosting, an official plugin and client onboarding remain deferred by
the user. Broader feature-path search and reasonable-effort metrics are later
extensions; graph size or failure to find a path alone is not a difficulty verdict.
