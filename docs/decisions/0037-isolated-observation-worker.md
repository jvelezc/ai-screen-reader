# Isolated observation worker

The trusted native coordinator executes the fixed `observe-fixture` stage through a narrow PostgreSQL adapter and an independently isolated Chromium CLI process. The worker references Domain only; Directory.Build.targets enforces this. It does not load Playwright, the reader engine, an HTTP host or storage SDK. Npgsql10.0.3 is centrally pinned and locked. Its [data source and positional parameters](https://www.npgsql.org/doc/basic-usage.html) keep values separate from SQL. Parameter logging and database error details are disabled.

The coordinator holds the database connection and bearer capability. Its runtime role receives only the four fenced functions. Server renewal reconfirms authority before browser allocation; a five-second heartbeat renews during execution/persistence. Failed renewal cancels execution and joins actual owned cleanup. Actual renewal calls settle before completion. Database completion/blocking failures remain Unconfirmed with safe identity/error code. Polling halts on an unconfirmed outcome. Lease expiry is never physical browser-stop evidence.

The internal CLI `--worker-fixture` accepts only organization, scan, job and generation on stdin. No URL, input, credential, capability or storage path is accepted. It captures the initial bundled synthetic-shop snapshot, closes its actual owned Chromium, then emits a bounded receipt. Exact fixture hash/profile bind semantics; zero dispatched input and no goal verification are explicit. The original four-second process confirmation and five-second native cleanup deadlines remain intact.

The parent launches a local immutable image ID with pulling disabled. The browser container has networknone, no published ports or host mounts, nonroot1001:1001, a read-only root, dropped capabilities except the sandbox's required SYS_CHROOT, no-new-privileges,2CPUs,1GiB RAM,256tasks and bounded private tmpfs/shm. Docker uses the established Chromium seccomp policy. The parent inspects isolation before start. Runtime subprocesses inherit an explicit environment allowlist; the browser receives no environment pass-through. Database/Supabase credentials never enter browser descriptors, environment, arguments or reports. The operator controls the runtime, image and private evidence root.

Runtime commands and stdout/stderr are bounded; private stderr is discarded. Cancellation stops the owned runtime client and performs independently bounded container cleanup. Only the exact random name with its matching owner label may be removed. A missing image fails without a registry pull. Execution returns only after removal is independently confirmed. Failed cleanup retains an unconfirmed ownership outcome.

Receipt validation requires exact tenant/scan/job/generation, fixture hash/profile, epoch, bounded nonempty snapshot, settled shutdown and timely exit. JSON is bounded to1MiB, rejects duplicate/unknown fields, requires constructor data and explicitly checks shutdown facts whose omitted defaults could appear successful. See [required constructor parameters](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/required-properties) and [duplicate rejection](https://learn.microsoft.com/en-us/dotnet/api/system.text.json.jsonserializeroptions.allowduplicateproperties?view=net-10.0).

The coordinator copies validated original bytes, writes a unique pending file, flushes to disk, renames without overwrite, reads back and hashes. Only then may the current capability complete the database stage. The canonical relative path contains tenant/scan/job/generation. A rejected/lost completion acknowledgement retains an unconfirmed orphan receipt, never overwriting prior bytes or inventing a completed scan. SQL still fences completion and actual queue deletion transactionally. This is private local persistence, not S3 finalization or distributed filesystem/database atomicity.

The worker supports `--once` and `--poll`. Operator-private service configuration supplies HSR_WORKER_DATABASE, HSR_WORKER_IMAGE (local sha256 image ID), HSR_WORKER_EVIDENCE, optional HSR_WORKER_RUNTIME (podman default), and HSR_WORKER_SECCOMP for Docker. Non-loopback PostgreSQL requires explicit runtime credentials and hostname/certificate-verified TLS. Never use an administrative/service-role credential. Linux SIGTERM and Ctrl+C request joined cleanup. Do not configure automatic restart after an unconfirmed outcome: native crash recovery and retained ownership journals remain a separate supervisor gate.

The isolated acceptance runner uses actual PostgreSQL/pgmq, a narrow disposable login and separate networkless Chromium. Synthetic users exist only inside the disposable database. It exercises native claim/renew/complete/block, exact byte/hash binding, immutable attempts, acknowledged queue deletion and blocked-engine archiving. CI adds this independent Linux job to the existing eight jobs.

Admission and lease schemas are installed in the selected Supabase project after accepted CI; the native worker is not deployed yet. CI/VPS deployment, host crash recovery, live JWT onboarding, private S3 finalization and viewer integration remain separate gates. This stage enables no arbitrary targets or input. Public MCP hosting/plugin publication remain deferred.
