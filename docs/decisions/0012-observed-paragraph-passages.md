# 0012 Observed paragraph passages

Status: accepted. Date: October 19, 2026. Profile: hsr-desktop-reader-v11.

Reading one AX text run at a time can split a word or sentence at emphasis and links. Add an independent paragraph passage without changing the existing single-run character, word, newline or UTF-16 offset contracts. Domain defines ReaderTextPassage as an immutable sequence of source ReaderTextRange fragments. Its Text is exact concatenation with no inserted separator, whitespace trimming, DOM text fallback or accessible-name substitution.

ReadCurrentParagraph reads the current observed paragraph or its known enclosing paragraph. NextParagraph and PreviousParagraph traverse exposed paragraph nodes in observation order without wrapping. PreviousParagraph leaves the enclosing paragraph when invoked from a descendant. Paragraph commands require browse mode, dispatch no browser input, do not move browser focus and reject semantic goal expectations. They clear the single-run text selection and anchor the reader cursor on the encountered paragraph. Unknown, unsupported and empty encounters remain explicit instead of being silently skipped.

A passage requires complete observed ancestry to its document root and consistent document/frame identity. It accepts exact StaticText and LineBreak sources under known textual inline roles, including links and emphasis. InlineTextBox nodes are not repeated as text. Missing source text, conflicting ownership, overlapping source runs and named links without observed text return Unknown. Controls, images, nested paragraph blocks and other nontext content boundaries return Unsupported with no partial passage. Ordinary accessible names remain separate from text sources.

Limits are 128 source runs and 32768 UTF-16 code units per paragraph. An over-limit paragraph returns Unsupported and no passage. The passage stores complete per-run offsets, identities, frames and semantic sources; ordered announcement events retain that same passage. Each command uses fresh bounded observations: rereading changed text returns the new passage, while previous immutable steps/events retain their earlier sources. Removal or document replacement invalidates the reader cursor; ReadCurrentParagraph cannot return the old passage and requires re-anchoring through navigation.

This is logical exposed paragraph reading, not rendered-line reconstruction, cross-paragraph word navigation, an editing API, speech scheduling or an AT compatibility claim. Child paragraphs can be read independently in supported trusted frames; excluded frame coverage stays explicit. Domain remains infrastructure-free, ScreenReader depends only on Domain, and the existing Chromium adapter supplies all semantics. No new framework, package, external-site route, credential entry or recording capability is introduced.
