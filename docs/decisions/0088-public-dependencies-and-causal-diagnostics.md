# Public dependencies and causal diagnostics

An exact-host rule is appropriate for selecting the task's document, but it prevents a modern website from loading third-party services. A blanket GET/HEAD rule also blocks normal OPTIONS/POST API traffic. Neither failure establishes an accessibility barrier.

The admitted navigation-task launcher and browser now select `PublicHttpsDependenciesV1`. Top-level navigation remains GET/HEAD on the exact admitted source. HTTPS dependencies may use ordinary API methods and public DNS hosts without a per-host allowlist. Secure WebSockets are forwarded through the same configured proxy. The independent namespace fence, TLS certificate verification, DNS public-address validation, mixed-answer rejection, single-resolution IP pinning, anonymous fresh contexts, lease checks and input authorization remain active. Private/literal/reserved destinations and insecure/custom-port traffic remain unsupported.

The public-dependency proxy permits 64 concurrent website tunnels, a 64 MiB per-direction tunnel budget and a 180-second tunnel deadline, inside the existing one-shot task deadline. Legacy exact-host callers retain their original constructor, method, 16-slot/10 MiB/30-second behavior. Session control is processed before acquiring a website slot, preventing website requests from starving lease heartbeats or diagnostic reads. Reading diagnostics cannot renew the lease.

Original reports retain bounded redacted browser request lifecycles and an independent proxy trace. Browser records distinguish request/response/finish/failure/policy denial, method, type, destination origin, request ID, sequence, timestamp, status, safe failure code and URL fingerprint. The original URL path/query, cookies, headers, bodies, WebSocket messages and raw exception strings are not retained in diagnostics. A full-URL SHA-256 is a correlation fingerprint, not a retrievable URL. Browser-launch failures carry bounded traces on the existing framed control channel; discovery without a supported goal retains its own trace.

Operation failures retain their actual stage/category/code, time, last recorded input event and up to eight first-party method/source-basename/line/IL-offset frames. Generic frames use type definitions, not runtime argument values. Absolute machine paths, exception messages, locals, and third-party frames are excluded. At most four failures per attempt are retained; omitted failure counts remain explicit. Fatal errors retain this context in the scoped framed failure diagnostics even when no original report can be published. The table links operation failures to their exact original failure entry.

All traces are bound by the original report's review/job/worker/execution and producer digest. At most 256 events per trace are retained; later coded errors displace routine entries. Counts and dropped events remain explicit. An authenticated private `HSR-TRACE` read exposes only the same proxy session, rejects wrong/absent/expired authority and does not extend the lease. Expected isolation probes are marked by their ending sequence and excluded from the website issue table.

Core API 1.21/private MCP result responses include at most 32 issue rows derived from the verified original. Each includes a stable case ID, observed fact, next troubleshooting action, timestamp, attempt, request/event IDs, destination origin and original JSON evidence pointer. Larger tables and missing/truncated traces remain explicit. The existing Supabase Edge result route transports this additive response; the consumer must accept the optional `diagnostics` field before core promotion. No engine/assessment logic moves to Edge or UI.

A failed keyboard attempt with unexplained network errors, truncated diagnostics or unconfirmed WebSocket exchange cannot become a proven barrier. A positively observed task goal remains a success for that task despite incidental requests. WebSocket initiation and TLS connection are not proof of handshake/message exchange; the current trace explicitly preserves that uncertainty. Old reports omit the new fields and retain their original policy and assessment.

Every discovered issue and its reproduction/regression belongs in [the issue catalogue](../validation/issue-catalog.md). Raw network records explain technical observations; corrective actions are troubleshooting guidance rather than a claim that a specific unobserved cause or legal conclusion has been proved.
