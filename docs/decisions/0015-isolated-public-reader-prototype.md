# 0015: Isolated approved-public-page MCP prototype

The user requested a working reader another AI can use. Local stdio MCP and fixtures were already verified in decision 0014. This increment adds a bounded public reading and link-navigation path, after target policy and external network enforcement passed live probes.

Domain owns exact HTTPS target and public-address decisions. The nonempty Egress console references only Domain and implements bounded CONNECT TLS passthrough, one validated DNS resolution pinned to an IPv4 socket, private TCP/UDP control sentinels, resource leases and worker probes. Browser.Playwright still references only Domain; ScreenReader still references only Domain. The MCP host composes the verified isolation receipt, browser and reader. No control-plane, database or hosted authorization framework is introduced.

The Linux worker shares a private network namespace with a separate fence container. Only the fence has NET_ADMIN; both IP families default to DROP. The worker can reach only proxy TCP3128 and its own loopback. The proxy bridges the private and egress networks and allows approved public DNS targets on TLS443. A nonroot browser, read-only filesystem, no-new-privileges, bounded tmpfs/resources and Chromium sandboxing add independent controls. SYS_CHROOT is the worker's sole capability, required for Chromium's sandbox chroot; Docker uses Playwright's published seccomp profile to permit user namespaces. No sandbox-disable flag, host mounts, published ports or host networking are used.

Before public tools become available, the host checks actual uid/capabilities/mount flags and live network behavior, including private sentinel, direct public IPv4/IPv6, denied authorities and certificate-verified approved TLS. The launcher separately proves the sentinels were live outside the fence and inspects all six default-drop kernel policies. A failed check prevents startup. The tested gate preceded addition of reader_open_url.

Public input permits traversal and Enter on actual noneditable link focus only. Controlled fixtures retain supported widget actions. This intentionally avoids public form/button workflows until capture exclusion and stronger action authorization are designed. An input completing does not verify the destination; a fresh document and explicit semantic goal do. Page text remains untrusted data. The browser reports blocked resources, unsupported frames and incomplete observations rather than fabricating semantics.

Each launch owns labelled containers/networks. Cleanup verifies ownership. Heartbeats expire after 15 seconds without a pulse, cannot revive expired leases and stop the proxy/fence after abrupt client termination; a 30 minute absolute lifetime remains. Unused labelled networks are removed on subsequent launches without force or global pruning. CI exercises core/browser tests on Windows and Linux and the complete public MCP task inside a Docker fence on Linux. Public HTTP availability and live markup are external acceptance dependencies; failures remain visible.

This completes a usable local prototype, not the full hosted platform. Signed-in pages, credentials, capture exclusion, recordings, storage, host supervision, remote MCP authorization, human takeover and production deployment remain separate milestones. Claude MCP connectivity can be verified without a model; Claude-driven acceptance requires the user's client login.
