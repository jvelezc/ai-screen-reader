# Private worker deployment through SSH

Status: implemented locally; CI, provisioning and live acceptance remain separate gates. The user selected private SSH access. No public MCP/plugin endpoint, Caddy edit or new listener is introduced.

CI produces the release from the same immutable fixture image and worker binary closure exercised by its real PostgreSQL/Chromium checks. It copies the complete tested runtime output without rebuilding or regenerating dependency metadata; the file inventory and every worker file hash must match. The outer archive binds the source commit, immutable image configuration ID and every file hash. The host also checks the actual Docker archive configuration bytes, so an unrelated archive cannot pass by finding an old image in its cache. Release artifacts expire after one day; smaller test/deployment receipts remain separately retained.

Promotion verifies the exact successful main CI workflow, repository, all nine existing jobs, current source head and one nonexpired release artifact. It downloads that artifact rather than building a replacement. Deployment is serialized and uses strict host-key verification and a fresh restricted SSH credential. Bootstrap remains disabled until the operator provisions the selected host and enables its dedicated repository setting.

The root-owned forced command accepts only a forty-character commit in the fixed deployment protocol. It validates bounded regular archive entries, exact file lists and hashes before installing an immutable release under /srv/headless-screen-reader. It never extracts links or executes supplied shell commands. The dedicated deploy account can invoke only that root-owned helper. The separate worker account runs rootless Podman; its browser receives the fixed nonsecret descriptor, with no host mounts, network, database credential or deploy credential.

The operator bootstrap refuses unknown accounts and unowned paths. It installs only this application's accounts, files and service. A pinned app-specific Supabase certificate supports VerifyFull without changing global trust. The runtime database login inherits only the existing narrow hsr_worker function grants; management credentials remain on the operator's computer. Environment configuration stays outside release artifacts. App-owned directories are opened without following symlinks before ownership/permission changes.

Readiness first runs --check-runtime through the actual isolated executor and original observation/shutdown validation. It has no database/admission path and saves no admitted observation. Its root is separate from tenant evidence. Only after exact owned resource recovery and a successful runtime canary does the helper change the release pointer and start the service. Database readiness requires a fresh systemd invocation's actual Empty/Observed worker receipt and a final active invocation/PID check. An empty queue alone cannot establish browser readiness, and readiness is a point-in-time observation.

A failed deployment stops the service and reconciles actual native ownership before attempting the previous release. Unknown cleanup holds closed; it does not authorize restart. Release switching is atomic and flushed. A failed pointer flush after rename is treated as an attempted switch requiring recovery. Actual pending work, native absence, observation, database completion and goal verification remain different facts. Restart=no prevents automatic loops past an unconfirmed result; boot/manual startup still performs retained native recovery.

The CI batch allowance is20 minutes because the preceding Windows job needed14m10s including browser installation, the full suite, demos and artifact publication. This changes no browser, input, test or native ownership deadline. Actual exit confirmation must still precede4,000ms, with the original5,000ms ownership bound.

[Validation and remaining gates](../validation/private-worker-deployment-v1.md) distinguish native Windows regression, Linux operational unit checks, real Linux/Podman composition, remote CI and live deployment. The one-time bootstrap is an operator action over the already authorized root connection; that root key is never copied into GitHub. Private report/control API, real app JWT onboarding, private S3 finalization and human/AT validation remain later original-product work. Public MCP hosting and plugin publication stay deferred.
