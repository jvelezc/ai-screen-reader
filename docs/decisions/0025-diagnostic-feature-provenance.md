# Diagnostic feature provenance

Run the controlled inventory and four independent authored routes:

~~~powershell
dotnet run --project src/HeadlessScreenReader.Cli -c Release -- --features
~~~

The printed index links to each route's existing node/edge trace, reader evidence and a separate diagnostic table. JSON retains the original discovery ID, document/epoch, observed control, diagnostic source, bounds and actual related action references. Original receipts remain immutable.

This first inventory is deliberately limited to the trusted synthetic fixture's main document and at most 64 exposed noneditable buttons or links. It separately reads the declared data-hsr-feature attribute, at most 128 UTF-16 code units, through a fixed read-only function. This is an author-provided intent hypothesis, not a general feature classifier. Missing, oversized, unavailable and unconfirmed discoveries remain explicit. Hidden, unexposed and child-frame features are outside coverage. Public diagnostics are unavailable.

Ordinary accessibility snapshots and announcements never receive these diagnostic attributes. The unnamed synthetic button stays unnamed even though its diagnostic hypothesis says account-settings. A declared hint establishes neither actual functionality nor reader discoverability.

Diagnostic collection joins the browser capture-admission gate. It sends no keys and reads no editable values, URLs or general DOM text. Caller cancellation cannot release an underlying diagnostic operation from the adapter drain; late excluded results are rejected. Identity and observed semantics are checked before and after the sequential hint reads; this does not claim an atomic snapshot.

The pure provenance projection binds each candidate to the first retained route observation using document, capture epoch, node identity and exact initial semantics. Subsequent focus or state changes remain actual observations of that same scoped target. Related actions reference only authored attempts that encountered it, including unresolved attempts with no result node. Foreign documents, resumed epochs, missing or changed source nodes, and unconfirmed discovery yield explicit binding states with no path links.

Route reachability and goal verification remain separate from every diagnostic candidate. No shortest-path, feature-success, global completeness, accessibility-conformance or reasonable-effort result is inferred. See [validation](../validation/diagnostic-feature-provenance-v1.md).

Reject stale, uncertain, incompatible or ineligible evidence. An eligible request must execute reader commands under current browser policy, create a separate run/attempt result and retain links to the historical request without overwriting it. Test equivalent fresh DOM instances and same-URL changed states. Do not turn passive evidence selection into live execution, replay historical browser keys blindly, or enable public consequential actions.
