# Private workspace and fixture reports

The deployed worker needs a usable private client. Add the composition to the existing CLI with `--hosted-control`: a loopback-only ASP.NET Core portal, fixed-project Supabase Auth verification, tenant-scoped admission and verified observation reports. Domain, ScreenReader, Browser.Playwright and Worker keep their existing dependency boundaries.

Users sign in directly with the selected Supabase Auth provider. Passwords never pass through our control API or observation worker. The portal keeps the access bearer in memory, sends it only in an authorization header, persists no refresh bearer and revalidates the user with the fixed project's `/auth/v1/user` on every tenant request. PostgREST receives that same original user bearer and applies existing tenant RLS. The public configuration accepts only a publishable key or this project's legacy anon key; no privileged database, management or service-role credential belongs in the portal.

`hsr.ensure_personal_workspace()` takes no identity argument. It locks the existing Auth user, atomically creates one personal organization and membership, and returns the existing mapping on retries. A revoked member cannot use bootstrap to restore access. Real concurrent PostgreSQL calls prove one workspace without orphan organizations. The worker's four narrow function grants do not change.

The UI admits only `synthetic-shop` with reader profile v13 and a client request UUID retained for an unconfirmed retry. Recent history is bounded to fifty runs with an explicit `hasMore`. A report authorizes its scan/job before reading a file; the original bytes must match the exact tenant/scan/job/generation reference, stored SHA256 and complete observation contract, including the existing native shutdown deadlines. Queued, blocked, unavailable and invalid evidence stay distinct. An available fixture observation dispatches zero browser inputs and does not verify an objective or establish accessibility conformance.

The report retains node IDs, parent IDs, roles, names and nullable state provenance. Unnamed nodes display neutral `(unnamed)` text. Diagnostic inference and editable values do not enter this projection. The UI clears private data on sign-out or access denial, guards overlapping Auth flows and renders observed content with text nodes.

The intended production access is an SSH forward from `http://localhost:6086` to VPS loopback `127.0.0.1:8086`. The existing worker deployment is accepted separately. This increment adds application code and SQL tests; it does not yet package or deploy the portal, expose the `hsr` PostgREST schema, apply the personal-workspace migration to the hosted project, or establish actual app-user acceptance. Public MCP and official plugin publication remain deferred.

Operator configuration is `HSR_CONTROL_PUBLISHABLE_KEY`, `HSR_CONTROL_EVIDENCE`, `HSR_RELEASE_COMMIT`, optionally `HSR_CONTROL_PORT` and `HSR_CONTROL_ORIGIN`. `/internal/ready` proves an actual listener and explicitly leaves app JWT/public MCP acceptance false. Protocol examples are [portal.http](../../src/HeadlessScreenReader.Cli/HostedControl/portal.http); `/openapi/v1.json` describes the bounded endpoints. Run with the documented pinned SDK and configure secrets outside tracked files.
