# HeadlessScreenReader

Local .NET screen-reader foundation for the architecture in [the development plan](outputs/HeadlessScreenReader-Architecture-Review-and-Development-Plan.md).

**Active work: the original evidence-backed workflow.** Bounded authored traversal, immutable attempt receipts, an observation graph and linked local reports are implemented. Run `--traversal` below. See [original milestone status and the next acceptance gate](docs/development-status.md). Public MCP hosting and plugin publication are deferred.

For a working local MCP prototype with approved public HTTPS reading, isolated link navigation and Claude configuration, see [Use HeadlessScreenReader with Claude](docs/prototype/claude.md). Public browsing requires a running Linux Podman or Docker engine; the trusted fixture connection also runs directly on Windows.

The optional [Claude instructions](docs/prototype/copy-to-claude.md) describe the existing local integration; client setup is deferred while the original workflow milestones progress.

The local increments run bundled synthetic pages in real Chromium. They demonstrate separate virtual cursor and browser focus, browse/focus command routing, widget state, dialog focus restoration, bounded destination verification, and an ordered command/observation timeline. Announcements are generated by HeadlessScreenReader; they are not NVDA recordings.

## Run the fixture demo

Prerequisites: .NET SDK 10.0.402 (selected by global.json), PowerShell 7, and network access for the first NuGet/browser installation. No application accounts or API keys are required.

Run these commands from the repository root:

```powershell
dotnet restore HeadlessScreenReader.slnx --locked-mode
dotnet build HeadlessScreenReader.slnx -c Release --no-restore
pwsh -NoProfile -File src/HeadlessScreenReader.Cli/bin/Release/net10.0/playwright.ps1 install chromium
dotnet run --project src/HeadlessScreenReader.Cli -c Release --no-build
dotnet run --project src/HeadlessScreenReader.Cli -c Release --no-build -- --widgets
dotnet run --project src/HeadlessScreenReader.Cli -c Release --no-build -- --text
dotnet run --project src/HeadlessScreenReader.Cli -c Release --no-build -- --frames
dotnet run --project src/HeadlessScreenReader.Cli -c Release --no-build -- --ranges
dotnet run --project src/HeadlessScreenReader.Cli -c Release --no-build -- --composites
dotnet run --project src/HeadlessScreenReader.Cli -c Release --no-build -- --tables
dotnet run --project src/HeadlessScreenReader.Cli -c Release --no-build -- --paragraphs
dotnet run --project src/HeadlessScreenReader.Cli -c Release --no-build -- --multiselect
dotnet run --project src/HeadlessScreenReader.Cli -c Release --no-build -- --typeahead
dotnet run --project src/HeadlessScreenReader.Cli -c Release --no-build -- --traversal
```

On Linux, install Chromium's system dependencies with the same Playwright command plus --with-deps. A visible local browser is optional:

```powershell
dotnet run --project src/HeadlessScreenReader.Cli -c Release --no-build -- --headed
```

The demo prints JSON lines. It reads a heading, finds a button with the virtual cursor, reports FocusRequired when browser focus differs, tabs to that button, and presses Enter. The final line must contain FixtureGoalReached: true. The fixture itself changes focus to its revealed heading, just as a website can.

The widget demo opens and closes a modal, checks terms, selects a radio option and delivery region, and waits for a delayed save heading. It then reports the observed disabled payment control. Its final line must contain both FixtureGoalReached: true and BlockedRouteObserved: true. Each Event line links an observation or action to its command sequence and monotonic elapsed time. Step lines report the command result; events are exported in sequence after the workflow.

The text demo prints source-tagged character/word/line ranges with UTF-16 offsets. Its final line must contain TextNavigationObserved: true and ReaderDispatchedNoInput: true. Lines are newline-delimited AX text runs; visual wrapping and words spanning multiple runs remain outside this increment.

The frame demo reads trusted embedded/nested documents and verifies a keyboard-activated child status change. Its final line must report ChildFrameObserved, ChildFocusObserved, ChildActionVerified and IncompleteFrameCoverageReported as true. Hidden and unsupported documents retain explicit coverage records. Defaults are eight captured documents and three child levels; the actual limits appear in the environment manifest.

The range demo verifies native and fractional ARIA slider changes through actual keyboard focus, observes exact progress values and preserves missing current values. Its final line must report RangeNavigationObserved, SliderValuesVerified, ProgressValueVerified and UnknownProgressPreserved as true. Numeric goals require exact observed values; they do not infer percentages or overall task completion.

The composite demo verifies tree hierarchy, read-only navigation, explicit tree activation and manually selected tabs. Its final line must report ReadOnlyBrowseObserved, TreeHierarchyObserved, TreeActivationVerified, ManualTabSelectionVerified and HiddenContentExcluded as true. Focus and selection are separate; collapsed children and hidden panels never count as observed. Tree peers use known exposed ownership and level, separately from declared logical positions.

The table demo finds a native product table, moves across cells and down a column, and associates "$3" with the observed Apples row header and Price column header. Its final line must report TableHeadersObserved, CellNavigationObserved, BoundariesPreserved, MissingHeadersRemainUnknown and ReadOnlyBrowseObserved as true. It sends no keyboard input and never moves browser focus. Native row/column positions include hidden content; they are not exposed peer counts. See [table validation](docs/validation/reader-tables-v10.md).

The traversal demo runs four independent synthetic shop routes: verified checkout preview, disabled checkout, validation dialog instead of checkout, and unchanged feedback. Its summary must report TraversalGoalVerified, DisabledRouteObserved, ActualDialogRetained and UnchangedRemainsUnknown as true. Open the reported `artifacts/traversal/<batch>/index.md` for directed SVG traces, equivalent traversal tables and transcripts. Each node is an observed state; each arrow identifies its reader command and actual browser-key attempts/completions. Each route also has an immutable JSON receipt and projected graph. No order is submitted. [Future feature-path assessment](docs/decisions/0018-feature-path-traces.md) will use these traces to assess reachability and reasonable effort; graph size alone is not a difficulty score. See [traversal acceptance](docs/validation/traversal-v1.md).

The owned evidence demo runs with `--owned-scan`. It persists command intents before dispatch, drains real file writes before acknowledging exclusion, resumes with a fresh epoch baseline and closes with no pending work. Open the printed folder for typed JSON and hashes. This proves a bounded local owner; hosted privacy, human takeover and credential entry remain separate gates. See [owned evidence exclusion](docs/decisions/0027-owned-evidence-exclusion.md).

The CLI also supports an optional manual comparison with NVDA:

```powershell
dotnet run --project src/HeadlessScreenReader.Cli -c Release -- --reference-case dialog
```

This keeps a headed fixture open for a real NVDA comparison, with no automated reader input or speech capture. Close its window when done. Use --reference-template to generate a blank JSON worksheet and --assess-reference <file> to check completed manual observations. See the [NVDA comparison procedure](docs/validation/nvda-reference.md) for all seven cases, metadata, known differences, and exit codes. Actual NVDA validation remains pending.

Use --help for the complete CLI syntax. It does not accept a target URL. Fixtures are embedded, service workers and downloads are disabled, and context HTTP requests are aborted. These restrictions are for this controlled fixture harness; they do not establish a sandbox for hostile websites.

## Git workflow and CI

This is a solo project: commit directly to `main`. Feature branches and pull requests are optional. Every push to `main` runs the [CI workflow](.github/workflows/verify.yml) on Windows and Ubuntu; it can also be started manually from GitHub Actions.

Each job restores locked packages using the pinned SDK, builds with warnings as errors and architecture checks, verifies formatting, installs Chromium, runs the full test suite (including real Chromium tests), and exercises the CLI demos. A run fails if no test results are produced or any discovered test does not execute and pass. Test results and synthetic demo output are retained for seven days. Fix a failed CI run before starting the next increment. Local success and a successful remote CI run are separate checks.

The Linux job uses Ubuntu 24.04 and loads an AppArmor profile granting user namespaces only to that runner's installed Chromium headless shell, following [Chromium's per-binary guidance](https://chromium.googlesource.com/chromium/src/+/main/docs/security/apparmor-userns-restrictions.md). Chromium sandboxing stays enabled; no machine-wide user-namespace setting is changed. This CI setup does not establish the later hostile-site isolation milestone.

Directory.Build.targets rejects external packages, hosting frameworks, or project dependencies in Domain and rejects dependencies other than Domain in ScreenReader. The Chromium adapter may reference Domain but cannot reference the reader implementation. See [architecture decision 0001](docs/decisions/0001-local-foundation.md).

All direct package versions live in Directory.Packages.props. Commit packages.lock.json files when intentionally changing dependencies, and use locked restore in CI. Nullable analysis and compiler/analyzer warnings are errors.

## Current behavior and limits

H/K/B/D bindings belong to the profile hsr-desktop-reader-v13. In browse mode they move the virtual cursor over exposed semantics. PreviousHeading/Link/Button/Landmark, Next/PreviousFrame, Next/PreviousRange, Next/PreviousTree, Next/PreviousTreeItem, Next/PreviousTabItem and DocumentStart/End provide browse-only navigation without input or wrap. PreviousLandmark skips known enclosing landmarks to leave the current context; parentage is never inferred from flat node order. In focus mode H/K/B/D dispatch h/k/b/d to the browser. Tab always uses actual browser focus; reaching an input widget switches to focus mode. Explicit raw keys are allowed only in focus mode and only under the local allowlist. Escape is an explicit keyboard command in either mode.

Next/PreviousListbox discovers exposed listboxes; Next/PreviousOption stays within a known listbox. Browse commands send no input or change selection. ListboxSelection carries source-tagged multiselectability and observed option states, separate from focus and active descendant. Activate can send one Space to an actually focused, enabled multi-select option with known local ownership and selected state. ExposedSelectionExpectation verifies an exact exposed set scoped to one live listbox/document/frame; hidden or virtual selections are outside that claim. The --multiselect demo must pass all six summary flags. See [v12 validation](docs/validation/reader-multiselect-v12.md) and [the selection contract](docs/decisions/0013-exposed-listbox-selection.md).

Next/PreviousTable discovers exposed tables (and explicitly unsupported grids). PreviousTable leaves the current enclosing table. Next/PreviousCell walks exposed cells in native row/column order within one table; from a row it enters that row. Next/PreviousRow retains the column, and Next/PreviousColumn retains the row. Missing cells and boundaries return NoMatch without movement or wrapping. These commands are browse-only and send no input. Header association is limited to exposed, named, same-table native headers with explicit scope="row" or scope="col"; absent or ambiguous support stays unknown. Spans, irregular layouts, outer tables containing nested tables, explicit headers links, declared virtual coordinates/counts, editable content and role overrides are unsupported; a simple inner table may be read independently. These rules are a bounded custom profile, not a complete HTML table-header algorithm.

ReadCurrentText reads the selected text range or current node's observed descendant text. Next/PreviousCharacter, Next/PreviousWord and Next/PreviousLine traverse source-tagged text runs without input or wrap. Characters are grapheme clusters; punctuation forms separate word units. Ranges carry document/node identity and UTF-16 offsets. Document/run changes or node removal invalidate selection with Unknown/TextCursorReset until explicit re-anchoring, such as DocumentStart. Text commands require browse mode and reject semantic goal expectations. See [the text contract](docs/decisions/0007-exposed-text-navigation.md).

ReadCurrentParagraph, NextParagraph and PreviousParagraph read an observed paragraph across inline text runs, including links and emphasis, without input or wrapping. Passage fragments retain exact source identity, frame, semantic source and per-run UTF-16 offsets; no spaces are inserted. The limit is 128 runs and 32768 UTF-16 code units. Unsupported content boundaries produce no partial passage; missing sources and named links without exposed text remain Unknown. Rereading uses fresh text, while earlier events retain their immutable passages. These commands require browse mode and reject semantic goal expectations. The --paragraphs demo must report all six summary flags true; see [the paragraph contract](docs/decisions/0012-observed-paragraph-passages.md).

Activation uses the currently focused supported control. In browse mode, a different virtual-cursor target produces FocusRequired. No locator click or injected focus is used to repair the path. A failed browser operation returns BrowserError and marks InputMayHaveOccurred when input had already been attempted; it is never reported as a website barrier.

DOM focus and aria-activedescendant remain separate observations. The active option supplies the announced focus inside a composite; keyboard input still goes to the DOM owner. An absent active target falls back to the exposed owner. The fixture's own website code manages modal focus and returns it to the invoker.

Results include Context: outer-to-inner exposed semantic containers and, for radios, options, tabs and treeitems with known ownership, a position among exposed peers. ExposedPeers counts do not claim the full logical size of a virtualized set. LogicalSet separately carries validated author declarations, including unknown size and invalid state. Required and protected-edit observations carry explicit source provenance. Snapshot-diff LiveRegionChanged events carry typed politeness, atomic/busy state and value-minimized text separately from the current-control announcement. Initial/unchanged/off/empty regions stay quiet; busy updates are deferred until observed settled.

ObserveChangesAsync provides bounded idle capture batches through the same controller gate, with explicit cancellation, duration, budget, browser-error and truncation states. It sends no input. Try `dotnet run --project src/HeadlessScreenReader.Cli -c Release -- --observe-live` for the trusted timed-update demo. These are sampled observations, not a speech scheduler or lossless event stream. Each document gets an initial live-region baseline. See [v11 paragraphs](docs/validation/reader-paragraphs-v11.md), [v10 tables](docs/validation/reader-tables-v10.md) and [v9 tree/tab validation](docs/validation/reader-composites-v9.md) for current bounded acceptance scope; [v8](docs/validation/reader-ranges-v8.md), [v7](docs/validation/reader-frames-v7.md), [v6](docs/validation/reader-text-v6.md), [v5](docs/validation/reader-landmarks-v5.md), [v4](docs/validation/reader-gaps-v4.md) and [v3](docs/validation/reader-context-v3.md) record earlier increments.

An optional ObservationExpectation verifies an exact exposed role/name with requested state or focus. The reader polls observations, never repeats input to make a predicate pass. Default wait bounds are one second, 25 ms between polls, and 50 checks. The adapter separately bounds each read-only capture at five seconds. Cancellation does not abandon an in-flight key. A wait timeout returns Unknown/TimedOut, and post-input cancellation returns Unknown/Interrupted. Neither proves a barrier. This is predicate verification, not general page quiescence or live-region speech scheduling.

Activating an exposed disabled control returns Blocked with OBSERVED_DISABLED_CONTROL and no browser input. This finding is scoped to that control and tested route. A keyboard policy denial returns Denied. InputAttempted, InputCompleted, Observation, GoalVerified, and the final result are distinct events. InputCompleted means the keyboard API returned, not that the website accepted the action. The in-memory timeline caps at 10,000 events by default and reports TimelineTruncated if exhausted; it is not durable evidence storage.

The snapshot omits editable values and editable descendants. Noneditable slider, meter and progressbar values are an explicit source-tagged exception; no percentage or task completion is inferred. The synthetic secret and account values are checked for absence in normalized output. This is a limited data-minimization rule, not general PII redaction: accessible names and ordinary page text may still be sensitive.

The main document and bounded trusted same-target about:srcdoc/about:blank child documents are inspected. FrameCoverage records observed, excluded, unsupported, unavailable and over-budget documents; it does not claim whole-site completeness. Node IDs and text ranges are scoped to document generations, child replacements invalidate affected cursors, and peer counts stop at document boundaries. Cross-target/out-of-process frames, arbitrary targets, rendered-line, cross-paragraph and word-level cross-run text flow, editable text operations, live-region speech scheduling and general dynamic-site settling remain unsupported. Supported widget examples remain the bundled checkbox, native radio group, select-only combobox/listbox, native modal dialog, form validation, native/ARIA sliders, meters, progress bars, single-select trees and manually activated tabs.

Names/descriptions, exact static text and primary states come from Chromium AX. Actual focus owners are observed separately in each supported document. A fixed read-only semantic supplement adds native checkbox required, declared aria-required and logical set positions, password-type protection, and missing range aria-valuetext with source provenance; no diagnostic inference or editable value read is introduced. Child AX trees are inserted at observed iframe owners. The [bounded live NVDA comparison](docs/validation/nvda-live-comparison-2026-10-18.md) covers v2; [targeted v4 observations](docs/validation/nvda-v4-targeted-comparison.md) preserve the original landmark difference, [fixed and rechecked in v5](docs/validation/reader-landmarks-v5.md). No fresh NVDA comparison was performed for v11; these checks do not establish full compatibility.

See [widget milestone validation](docs/validation/widget-milestone.md) for earlier local Windows and Ubuntu WSL results and reproducible commands, and [GitHub Actions](https://github.com/jvelezc/ai-screen-reader/actions/workflows/verify.yml) for remote Windows and Ubuntu CI results. There is no deployment. Actual NVDA observations now exist for selected fixtures; they do not establish broader assistive-technology compatibility.

The [comparison issue catalogue](docs/validation/nvda-comparison-issues.md) records the confirmed focus-mode cursor synchronization fix, earlier checks and live observations. The [v9 increment](docs/validation/reader-composites-v9.md) adds tree hierarchy/context, tree and tab browse navigation, and keyboard-driven expansion/selection after the range widgets in v8 and bounded child frames in v7. In focus mode, externally changed focus and active descendants keep result and announcement node IDs aligned; browse-mode cursor independence is preserved.

These local increments do not complete Milestone 0 and Milestone 1. The public MCP prototype has a separately tested Linux container egress fence and exact approved-host policy; it supports reading and focused link navigation. NVDA comparison is an optional external benchmark; the product is an independent screen reader for AI agents. General recordings, credential entry, human-control leases, Xvfb takeover, Supabase, S3 and hosted scanning remain open gates. Public MCP hosting and plugin publication are deferred.
